# 90-second Demo Scenario

## Demo Route

```text
기업 상세 → 지원서 → 채용 관리자 → 실무 시험
→ 시험 분석 → 채용 확정 → 신입 온보딩 → 온보딩 관리자
```

## Script

먼저 흑자의 상세 페이지입니다. 지원자는 이곳에서 회사와 주요 제품, 채용 정보를 확인하고 바로 지원을 시작할 수 있습니다.

기존에는 지원자 정보를 노션에 직접 옮겨 적으며 관리했기 때문에 지원자가 늘어날수록 입력과 정리에 많은 시간이 필요했습니다. Relay는 지원자가 웹사이트에서 본인인증부터 이력서 작성과 제출까지 직접 완료하도록 구성해 이 병목을 줄였습니다.

제출된 지원서는 관리자 페이지에 자동으로 정리됩니다. 관리자가 모든 이력서를 처음부터 끝까지 읽는 대신, AI가 경력과 직무 역량, 강점, 부족한 부분, 면접에서 확인할 내용을 구조화합니다. 관리자는 원문과 분석 근거를 한 화면에서 비교합니다.

서류 전형에 합격한 지원자는 2차 실무 시험으로 이동합니다. 지원자는 과목별 기술 문제에 서술형으로 답하고, Relay는 최종 답안과 문항별 풀이 시간을 평가 데이터로 연결합니다.

시험이 끝나면 관리자 화면에 과목별 이해도, 답변의 정확성과 근거, 논리의 일관성, 강점과 추가 확인 항목이 표시됩니다. 단순 정답률이 아니라 실제 문제 해결 역량을 함께 검토할 수 있습니다.

최종 합격자가 결정되면 채용 과정에서 축적된 정보는 온보딩으로 이어집니다. 신입사원은 업무 문서를 기반으로 질문하고, 맞춤형 미션과 AI 피드백을 받으며 부족한 역량을 보완합니다.

관리자는 온보딩 관리자 화면에서 구성원별 진행률과 미션 결과, 도움이 필요한 영역을 확인합니다.

결과적으로 Relay는 지원서 접수의 병목을 줄이고, 평가 자료를 구조화하며, 채용에서 발견한 역량 정보를 입사 후 성장 과정까지 연결합니다.

## Screen Checklist

1. 기업 상세 페이지의 핵심 메시지와 제품 섹션
2. 채용 공고와 지원서 작성 화면
3. 지원자 목록과 지원자 상세 AI 분석
4. 시험 개요와 과목별 답안 작성
5. 기술시험 과목별 분석 결과
6. 채용 확정 상태
7. 신입사원 오늘의 미션과 문서 기반 AI 채팅
8. 온보딩 관리자 구성원 현황

## Demo Safety

- 실제 개인정보 대신 시드 데이터를 사용합니다.
- PASS는 로컬 MVP 우회 모드로 진행합니다.
- 최종 제출과 상태 변경은 시연 전 복구 가능한 데이터를 준비합니다.
- AI 서버가 unavailable인 경우 저장된 분석 결과가 보이는 시나리오를 준비합니다.
- 각 화면을 새 탭에 미리 열어 네트워크·빌드 대기 시간을 줄입니다.
